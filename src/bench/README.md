
## Benchmarking

Run intermediate steps individually:

- Benchmark files

  The benchmark reads `data/cbs/file.<format>` with `sav`, `sav_row_compress`,
  and `dta` formats. These are generated by `src/snake/create_stat_file.py`
  (1M rows, 30 numeric columns); a missing file is regenerated by
  `make bench`. Run the benchmark with `make bench [sav|sav_row_compress|dta]`:
  with no format goal all formats are benchmarked, e.g. `make bench dta`.
  Use `BENCH_REPEATS=3` to run the whole benchmark three times (each run
  appends its rows; `plot_bench.py` averages over the runs).
  Results are appended to `results/bench.csv` with columns
  `language,task,tool,format,size,elapsed,branch` (`size` is the dataset label
  `cbs`; `branch` is the `duckdb-read-stat` branch the extension was built
  from).

- Scaling benchmark

  `make scaling` uses the row-compressed files in `data/scaling/`
  (`test_100k`, `test_1m`, `test_10m`; the 50M file is opt-in via
  `SIZES="100k 1m 10m 50m"`). Results go to `results/bench_scaling.csv`.
  The benchmark illustrates the quadratic running time when using chunking
  in pyreadstat. It uses SAV REL compressed files; similar patterns are found
  for sas files, but we don't have an open-source tool to create them.

- Plots

  `make plot` draws all figures from both CSVs into `results/figs/`:
  `mean_timing.png` (python read, R read, and a separate read + write-parquet
  panel), `duckdb_speedup.png` (the same panels as speedup of DuckDB over
  pyreadstat/haven, per branch) and `scaling_time.png` /
  `scaling_time_per_row.png` for the scaling benchmark (series labelled with
  their file format; rows from the `parallel-proto` branch are excluded). All branches are plotted
  by default (`--branch` restricts the figure to one): DuckDB bars/lines are
  split by branch (one color per branch in the bar chart, a different marker in
  the scaling charts) while pyreadstat/haven results are pooled across branches
  into a single bar. `mean_timing.png` has one legend at the bottom mapping each
  color to its tool/branch (`pull reader`, `+ parallel`), with a footnote naming
  the branches those short labels refer to; error bars are drawn only for bars
  averaging more than one run.
  
  The figures report timing separately for the branch of the `duckdb-read-stat` 
  extension. The timings for the natives (pyreadstat, haven) are collected
  for each run on each extension branch and thus averaged. 

- Check that both tools return the same data

  `src/snake/verify_readers.py` reads the same chunk with pyreadstat and with
  DuckDB and compares the dataframes; `--chunks` selects how many chunks to
  compare (default 1):

  ```bash
  uv run src/snake/verify_readers.py dta --chunks 3 --chunksize 100000
  ```

  It exits non-zero on any difference. The `data/cbs` files contain no missing
  values and no user-missing ranges, so both tools must return identical data.

- Create the R environment (done automatically by `make bench` when `renv.lock`
  is missing)
  ```
  make renv
  ```

- Build the extension
  ```
  make build
  ```

### Projection pushdown / selecting columns
- The Python and R libraries support selecting columns; it makes reads faster, suggesting
some sort of projection pushdown.
    - In R, reading 1/3 columns of the sas file takes around 1/3 of the time. Reading the
    sav file has smaller speedup.
    - For pyreadstat, `usecols` leads also to faster execution
- In contrast, in DuckDB, the timing does not differ between
`select a, b from read_stat` and `from read_stat`.
    - In one case, the full takes 2.8s and 2 columns takes 2.7s.
